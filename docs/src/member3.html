FRACTL · STAGES 2–3 · MEMBER 3

Tooling, Verification & FRACTL Studio

How the project is built, proven and shown: the live studio with its 2D/3D views and GPU renderer, the tests that prove nothing old broke, and the offline bundle for the presentation laptop.

Flow: editor → studio.py (local server) → real fractlc --jit → .svg / .f3d → browser: Canvas 2D or WebGL2 on the GPU → the model grows in drawing order
IN ONE BREATH In Stage 1, Member 3's tools showed results the compiler had produced in advance. Now FRACTL Studio compiles whatever you type, live, with the real LLVM compiler, and grows the result on screen in the exact order the compiled program drew it — in 2D or in 3D on the GPU, with shadows and wind. Every Stage 1 tool is still there, and four test suites prove that all build modes draw identical pictures.

03FRACTL Studio — the server Stage 3

studio.py uses only Python's standard library. Each request writes the editor's text to a real .fr file and runs the real tools:

EndpointWhat it runs
POST /api/compilefractlc input.fr --jit --out … --emit-ir … --timings (or object + cc + run). Returns the drawing, the IR, each phase's time, and every command's output.
POST /api/inspectfr_frontend --json (optional --fractal, --iterations) — the live Stages tab
POST /api/irfractlc --ir-only in recursive, unrolled or --opt mode — IR side by side
GET /api/presetsthe 17 example grammars

Three real-world problems solved along the way:

  • Slow disk: from WSL, reading and writing Windows folders is slow — writing the meadow's output took about 0.3 s instead of 0.04 s. The server copies the compiler into Linux /tmp once and builds there.
  • "localhost" delay: Windows tries IPv6 first for localhost, but WSL forwards IPv4 and IPv6 separately, so every request waited 2 s for a fallback. The server listens on both; every address now answers in about 4 ms.
  • Two builds at once would overwrite each other's files, so builds are serialized with a lock.

05The 3D renderer — how the model "grows" Stage 3

Written directly against WebGL2 (no three.js). The ideas, in order:

  1. Instancing: there is only one small cylinder mesh and one small blade mesh. Each of the ~40,000 pieces is an instance — its start, end, radius, colour — so the GPU builds all the geometry in one draw call per kind.
  2. Birth times: each piece gets a time from its position in the .f3d stream. In the vertex shader a piece is invisible before its birth, then grows out of its base over a fraction of a second, glowing while it's new. That is the "watch it being built" effect — it replays the exact order the compiled program drew. Together mode lets every instance grow at once (grass sprouts while the tree climbs); Emission order is strictly sequential.
  3. Grass: consecutive blade pieces are joined into whole blades; each piece knows how far along its blade it sits. That gives a pointed tip, dark-root-to-light-tip shading, occasional dry tips, and wind that bends each blade by the square of that distance (roots stay put).
  4. Light: sky + sun lighting; blades let light through when the sun is behind them; distance fog; the newest piece is marked by a glowing light.
  5. Shadows: a shadow map — the scene is first drawn from the sun into a 2048×2048 depth texture; then each pixel checks whether it is hidden from the sun (9 filtered samples for soft edges). The tree shades the grass and the grass shades the ground.
  6. Bark: procedural, in each branch's own coordinates so it wraps without a seam: long fissures, dark cracks, fine grain, moss near the ground.
SAY IT LIKE THIS "The browser never invents geometry. It receives the exact list of pieces the compiled program wrote, in the order it wrote them, and the GPU grows each one at its moment. On this laptop's integrated Intel graphics that's 40,000 pieces with shadows and wind at 60 frames per second."

08The offline bundle

make bundle produces dist/FRACTL-Studio (and a 15 MB zip): static fractlc and fr_frontend, the runtime, the studio, the demos, the classic UI, the stage viewer and the docs. The presentation laptop only needs WSL with Python.

  • Launch FRACTL Studio.bat: starts the server in WSL, waits until it answers, and opens Edge as a clean app window.
  • Check FRACTL Setup.bat: checks WSL, Python and the compiler, and does a real JIT build of the meadow with its time.
  • A settings switch turns shadows and wind off for a very weak GPU (not needed on this laptop: 60 fps on integrated graphics).

10Questions you may be asked

Is the growth animation pre-rendered?
No. Each Build runs the compiler; the animation replays the pieces the compiled program just wrote, in its drawing order. Change the seed and you get a different tree.
Why write your own renderer instead of using three.js?
No third-party code, nothing to download, and full control: growth from birth times, grass shading and wind all live in our own shaders.
What does the GPU do, and what does the CPU do?
The CPU compiles and runs the program (well under a second). The GPU draws: instancing, growth, lighting, shadows and wind.
How do you know the new compiler draws the same as the old one?
The mode-equivalence and golden tests compare output files byte for byte across every build mode and against the Stage 1 and Stage 2 results.
What if the presentation laptop has no WSL?
The setup checker says so and explains the one-time install; the compiler itself needs nothing else because it is fully static.
